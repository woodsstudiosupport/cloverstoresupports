# Format examples only

These are examples, not published apps, developers, reviews or releases. Replace example domains, identity, version codes and content with real inspected data. Never add example records to the live arrays unchanged.

For issue submissions, put the JSON inside one fenced `json` block. Register the developer first, then submit the app with that stable developer ID. The publisher stamps the registered developer name; do not submit verification fields. A maintainer must approve. `release.json` demonstrates a reviewed metadata PR rather than a supported issue type.
